# Jev for Slay the Spire 2

The user's requested destination is automatic Ascension 10 play. Start with an observable A0 baseline; no A10 capability or win rate is claimed. Keep existing mods enabled, as explicitly requested. No save edits, ascension unlock edits or game-rule changes are part of this setup.

## Start and control

Launch the game through Steam (direct EXE launch does not initialize Steam correctly). Double-click `Jev STS2.cmd` in this project, then open http://127.0.0.1:4317/. Start or continue a single-player run and press Autoplay. The compact panel is at http://127.0.0.1:4317/sidecar.

Preview asks Jev without acting. One move makes one decision. Autoplay continues until a stop condition. Pause prevents subsequent dispatches but cannot undo a move already sent; wait for pending work and animations before taking over. If an action times out, inspect the game and use the dashboard's explicit acknowledgment button before resuming. Never blindly repeat a timed-out move.

The runner restores paused. A changed run identity clears prior-run decision memory and pauses. Session totals persist across restarts. The default limits are 2,000 successful provider calls and 30 million input tokens; one request may exceed the token threshold. They are stop thresholds, not hard billing caps. TypeSafe currently lists $0.042 per million input tokens, output free, so the default token threshold represents about $1.26 plus any overshoot or unaccounted failed calls. Verify with provider billing. Set `MAX_DECISIONS` and `MAX_INPUT_TOKENS` before launch to change limits. Requests pin the model to `jev-1.13.0` (override with `JEV_MODEL`), so a new provider default can't change the model in the middle of a comparison; each response logs the model that answered. Restarting alone does not reset usage.

Only one runner should control the game. The operator lock is `.private/sts2/runs/operator.lock`. If an unclean shutdown leaves it behind, verify its recorded process is no longer running before removing that lock. Do not launch a second agent or manually play while Autoplay is active.

## State sources

The bridge exposes current player, full permanent deck, combat piles, hand, energy, block, enemies, powers, intents, relic descriptions, potion slots, map, rewards, events and shop state. Jev chooses among code-generated actions and short combat plans; only the first action is executed, followed by a new observation.

The save reader resolves `current_run.save` from the active profile reported by the bridge, validates its location beneath the game's save directory, parses the complete file and retains a hash. Jev receives a projection of visited map nodes, prior rooms, seen events and modifiers. Live state overrides checkpoint-era combat information. Hidden RNG and future draw order are not sent to Jev. The full raw save and API key remain local.

The live run ID uses the game's live start time and current save scope/profile. It must match the disk checkpoint. Save lag at transitions gets a bounded wait. Hextech's act-start rune screen opens before the new act is saved, so that screen alone may use the same run's previous-act history, explicitly labeled as such. Current choices always come from the live screen. The reader never writes the game save.

## Existing mods

All existing mods remain enabled. This is a modded-game baseline, not a vanilla benchmark. The installed Hextech Runes variant is 0.111.0. Its loaded registry contains 371 player runes, 54 forges and 140 enemy hexes; a read-only audit verified nonempty descriptions and decision-request routing for all 565 entries. Run `npm run sts2:check-runes` with the game open to repeat the audit after a mod update.

Every Jev request includes current equipped rune rules, visible counters, Hextech powers and the run modifier's active enemy hexes, including carried effects. Enemy tiers are 1/2/3. Combat, reward, upgrade, shop and rune-selection decisions retain these rules after request compaction. The dashboard lists the rules included in the last request. Hidden future rolls and private proc-tracking data are not sent; unexposed remaining proc counters are marked unknown.

Flying Kick's strict execution threshold/heal and Grounded's block doubling have focused numeric support, with guards for changed rules, duplicate instances, death effects and uncertain modifiers. Other active rune effects use all currently legal single actions and rule-based Jev judgment; speculative numeric outcomes and card-order projections are suppressed, and the game applies the actual mechanics before the next observation. This supports full-catalog rule interpretation, not exact simulation or individual in-game verification of every combination.

The adapter handles visible rune choice, confirmation, player-rune rerolls and enemy-hex rerolls. Jev compares rerolls with selecting now, including per-slot remaining uses, pending enemy previews, and an active shared golden upgrade. The installed normal flow charges no gold or HP for rerolls. Only current enabled buttons are exposed; revisions bind each action to its screen, slot, current identity and counters. Each screen permits at most 12 successful automated rerolls within the game's own limits. Unchanged acknowledged rerolls are not automatically retried. Enemy-hex removal/undo and self-pick catalogs are not automated. Unknown custom mod screens pause for inspection.

## Pile and draw-order awareness

Jev receives draw, discard and exhaust inventories with card multiplicity, current energy/star costs, upgrades and attached rules. Questions cover drawing now versus later, hand capacity, reshuffling, exhaust exclusions and selecting cards for top-deck/return/discard effects. Selection context includes the preceding executed card when it belongs to the same run and room.

The draw inventory is unordered. `known_draw_top` is a separately tracked next-drawn-first prefix from observed deterministic top insertions through the game's card-pile command. Those cards already exist in the inventory; they are not extra copies. Drawing consumes that prefix. Shuffles, random insertions, direct unrecognized mod reorders, validation mismatches and reloads clear knowledge. This does not inspect RNG or expose the unknown remaining order. Direct custom reorder methods conservatively produce unknown order.

The tracker harness runs with .NET9: build `integration/sts2-draw-tests/DrawTests.csproj` with `STS2GameDir` set to the installed game, then run its output with a .NET9 runtime. The game-supplied Harmony build does not support .NET10; the private portable runtime in `research/tools/dotnet9` was used here. Live hook loading is verified; a top-placement combat action has not been exercised since installation because the user requested a pause before the next run.

## Claude strategy layer

**Decision mode** is chosen from the dashboard dropdown (Jev baseline, Jev + strategist; the two route-facts modes are listed as deprecated) and persists across restarts (switching is refused while a decision is in flight):

- **Jev baseline** (default): `jev-compact-v1`, unchanged.
- **Jev + route facts**: `jev-compact-v2`. Adds `computed_facts` to every request (`integration/sts2/route-facts.mjs`): for each map option, the number of paths to the act boss and the min-max elites, rests, shops, unknowns, monsters and treasures along them. Off the map screen it gives what remains ahead from the current node, the rest site's real heal amount (from the game's own option text) with missing HP and wasted healing, potions held against floors to the boss, and gold against shops still reachable this act. In combat, `death_effects` gives on-kill damage (e.g. Waterfall Giant's Steam Eruption) against current HP each turn; forecasts previously listed it only as a note. Facts remove no options. The runner remembers the act map from the last map screen, because other screens don't include it. Replaying 1,150 logged decisions: no errors, about 250 extra tokens per request.
- **Jev + ordered route facts**: `jev-compact-v3`. Same as v2 except map options become order-aware: floors to the next rest and next elite, the most elites reachable with a rest since the previous elite, how far away shops are, rests excluding the rest every act places right before its boss, and up to three example room sequences in order (routes no other route beats on elites, rests and shops together). On map screens this adds about 210 tokens over v2. v3 also adds two second-look reviews through the existing review step. One fires when Jev uses a potion in a normal monster fight: in logged standard runs, all 24 hallway potions were drunk in round 1, mostly at 91–100% HP. The other fires when Jev leaves a shop holding 100+ gold while a card removal, or a potion with a free slot, is affordable. The reviews remove no options. Replayed over the 8 logged standard runs they would fire about 4.6 times per run (about 23k tokens).
- **Combat forecast coverage** (`jev-compact-v3.1`, `claude-strategy-v2.1`, from 2026-09-28): the one-turn forecast models Cruelty, Spite, Pillage, Headbutt, True Grit, Feed and Blood Potion; each forecast lists `lastingEffects` (powers played, which keep working after this turn and are not in its numbers) and `notModeled` cards, and Jev is told a partial forecast means missing effects, not zero. v3 facts also add a card-order review, once per turn, when Jev attacks first while a non-attack setup card leads to at least 3 more forecast damage this turn. Runs before this change are labelled `jev-compact-v3` and `claude-strategy-v2`.
- **Enforced combat rules** (`claude-strategy-v2.1`, constrained mode only; `combatConstraints` in `integration/sts2/strategy.mjs`): (1) plays forecast to be fatal are removed when another play is forecast to survive; (2) in normal fights, potions are removed while HP is at or above the plan's `combat.hallway_potion_below_hp_percent`, unless every other option is forecast to die; (3) while the plan's `combat.focus_enemy` and another enemy are alive, single-target plays at other enemies are removed unless they kill them. Each rule keeps at least one option. Replayed on 2,959 logged combat decisions (all earlier runs, Claude and Jev-only): rule 1 fired 40 times and overrode Jev 5 times, all in lost Act 1 boss fights at 3-14 HP where Jev chose a fatal Defend or Armaments over a surviving line; rule 2 at a 50% floor overrode 55 hallway potion uses, mostly on turn 1 at full HP; rule 3, with the leader of a minion group as focus, overrode 11 plays, some reasonable (hitting a Gas Bomb), so Claude should set it only when sure.
- **Lethal and exhaust cards** (from 2026-09-28, after JEV1 v3 lost to Soul Fysh with it on 5 HP): the forecast now models Fiend Fire, Thrash, Cinder, Evil Eye, Body Slam, Howl from Beyond, Explosive Ampoule and Shackling Potion (enemy Strength loss lowers each forecast hit), and the Cruelty percent is read from the card (the pattern had lost its `d`). Random exhausts (Thrash, Cinder) are exact only when every eligible card is the same, otherwise the plan stops at a `random` boundary. Plan search keeps any line that wins the fight. A new first-priority combat rule, `take_lethal`, limits choices to plans forecast to win the fight and survive (quality not unknown), using the fewest potions. In that loss, round 12 offered Strike → Breakthrough → Thrash (lethal), but Thrash was unmodeled and Jev played it first, which exhausted the Strike; round 11 skipped Thunderclap → Fiend Fire (34 damage versus 16). Re-planned on 3,644 logged combat states: no errors, candidates with unknown damage fell from 4,971 to 3,024, and 58 states now show a forecast win.
- **Glossary and brief coverage** (`integration/sts2/glossary.mjs`, 2026-09-28): the brief builder copied only a `description` field, so shop relic and potion descriptions (`relic_description`, `potion_description`), event relic descriptions and keyword definitions sent by the bridge were dropped; they are now kept, and `brief.keywords` lists keyword definitions. Options still without a description (reward relics) and card or relic names inside option text ("Add Metamorphosis", "Obtain the Chosen Cheese") are looked up in the bridge wiki search over the profile's discovered cards and relics (exact name matches only, cached), and listed in `brief.glossary`. Combat consults include `combat_state`: energy, block, player powers, hand and pile counts.
- **Bridge event fix** (source, built, not yet installed): the state builder chose the Fake Merchant branch from `CanonicalEvent` but cast `LocalMutableEvent`; in Room Full of Cheese they differ and every state read failed. Both now use the mutable event.
- **Strategist inputs added 2026-09-28:** `enemies[].seen_pattern` (intents per round in the last three fights with that enemy, from the logs and live play, `integration/sts2/movesets.mjs`); `current_options[].past_runs` on card rewards and shops (times offered and picked, plays per fight after picking, floor reached, `integration/sts2/card-stats.mjs`); `event` name and page text (bridge now reads the mutable event's description; installed with the next bridge update). Reward screens are owned when a potion is offered with every slot full. Encounter keys count duplicates (`Bowlbug x3`); older uncounted plans appear as `similar_fight_plan`. In-combat choice screens from potions reach the strategist because the bridge omits `battle` there.
- **Relics and act routes** (2026-09-28): `new_relic` now fires at the first screen outside combat after any new relic (it waited 3 floors, so Unsettling Lamp from an elite reached the strategist only at the boss). A consult off the map, such as the act's opening Ancient event, no longer marks the act's routes as seen: its brief had no routes but its stamp set `route_act`, which suppressed `route_plan` in JEV1 v3.3 Act 2.
- **Rule order and Beckon** (after JEV1 v3.1, run 1790625284, lost Soul Fysh at 58% removed after entering at 82/82): the hallway potion floor now applies before `take_lethal`, which had forced an Explosive Ampoule at 80% HP when every forecast win needed it. A new rule, `play_hp_loss_cards`, removes End turn while a playable card that costs HP when held (Beckon) is affordable. In that fight Jev ended round 8 with three Beckons and 1 energy (38 to 18 HP). Across all logs this happened 5 times in 3 runs, at least 30 HP. Also new: per-turn HP-loss caps (Hardened Shell) are forecast, and `intangible_defense` keeps only the plays with the least forecast HP loss while every enemy is Intangible (in the loss, Jev ended an Intangible turn taking 13 when Uppercut's Weak forecast 9). Replayed on all logged combat decisions it would have overridden Jev in 15 of 37 Intangible turns, typically 12-19 HP lost reduced to 3. JEV1 v3.2 (1790626491): Soul Fysh 81% removed. `block_not_needed` now counts only damage block can stop (Beckon HP loss ignores block) and reads End turn before the Beckon rule removes it; in that fight Jev blocked on a buff turn while two Beckons cost 12 HP.
- **Fixed rules** (also constrained mode only): pure block cards (`Gain N Block.`) are removed when ending the turn now is forecast to lose no HP and nothing uses block (Juggernaut, Barricade, Blur, Calipers, Body Slam-style cards); resting is removed when at least half its heal would be wasted and Smith is offered; a single-card exhaust choice (Toasty Mittens, True Grit+) is limited to status, curse and exhaust-payoff cards, else plain Strikes (below 30% HP) or Strikes and Defends, when those exist. Claude's `allowed_option_ids` for a screen override the rest and exhaust rules. Replay on the same log: block rule overrode Jev 51 times (e.g. Defend then End turn with no attack coming), rest rule 10 of 43 rests (e.g. resting at 72/80), exhaust rule 16 picks (e.g. exhausting Bash, Molten Fist or Pommel Strike while a Strike or Defend was in the choice).
- **Claude decides run-shaping screens** (`claude-strategy-v3`, from 2026-09-28): card rewards, shops, events, rest sites, treasure, Hextech runes and card selections outside combat always consult Claude (trigger `owned_screen`). `allowed_option_ids` is an ordered list: the first option still offered is taken directly, so a shop answer is an exact purchase list ending with leaving. Claude is asked again when none of the listed options is offered (for example a new event page). Setting the strategist status field `ownScreens` to false restores the older behaviour of consulting Claude there only when Jev is unsure.
- **Encounter playbook** (`integration/sts2/playbook.mjs`, `.private/sts2/strategy/playbook.json`): plans carry a `fight` field (`plan`, `target_priority`) scoped to one encounter, keyed by the enemy names at fight start. Elite and boss starts consult Claude every time; a normal fight consults once (trigger `new_encounter`) only when its encounter has no saved plan. Saved plans are reused across runs and shown to Jev only in that encounter (`fight_plan`), so they never carry into another fight. `target_priority` replaces `combat.focus_enemy`: while two or more enemies are alive, single-target plays at anyone but the highest-priority living enemy are removed unless they kill. Entries are enemy names or selectors resolved against live enemies each turn: `lowest_hp` (HP plus block), `biggest_attack` (largest shown attack), `can_kill` (an enemy some candidate's forecast kills). The first entry that matches picks the focus. Replayed as a blanket `["can_kill","biggest_attack"]` on 965 logged multi-enemy decisions, it would have overridden Jev 130 times, some wrongly (Corpse Slugs, where damage should be spread), so selectors are set per encounter only where clearly right. Answers on owned screens are remembered per screen for the run (returning to a shop after a card-removal screen reuses the list), and an owned screen with a single option is taken without asking.
- **Replay mode** (`integration/sts2/replay.mjs`): `start-run --replay-from <run>` writes `.private/sts2/replay.json`. On that new run, every non-combat screen whose options exactly match the reference run takes the logged choice (decision source `replay`, no Jev or Claude call). The first owned screen that differs is logged as `replay_diverged`, and play continues normally. Combat is never replayed, so Jev's combat play and the game's later shuffles still vary.
- **Jev + facts + Claude strategy**: `claude-strategy-v2`, using v3 facts. As below, plus routing: the first map screen of each act triggers `route_plan`, and the brief lists the distinct room sequences from the current node (e.g. `M?ER$EB`), each with node IDs. The plan's `route_path` (node IDs) and `elite_min_hp_percent` are enforced in constrained mode: map options are limited to the next node on the path, so a single one moves without a Jev call. `route_off` (no option on the path) and `route_risk` (next node is an elite and HP is under the threshold) trigger a new plan. The CLI rejects route nodes that aren't on the act map.

`CLAUDE_STRATEGIST=off` hides the Claude mode.

With strategy on, Jev still makes every move. Claude, running in the operator's Claude Code session on the subscription plan (no Anthropic API key or SDK), writes a persistent run strategy on specific triggers. This is event-triggered hierarchical control: a slow planner, a fast decider, and deterministic code between them. Policy label: `claude-strategy-v1` (Jev-only decisions keep `jev-compact-v1`, so logs separate the two for comparison).

**Triggers** (`integration/sts2/strategy.mjs`), evaluated before Jev on every non-forced decision:

- `run_start`, `new_act`, `boss_start`, `elite_start` (round 1 of that fight)
- `low_hp`: HP falls below the plan's `replan_below_hp_percent` (Claude sets 10-60; default 25)
- `rich_shop`: entering a shop with 150+ gold
- `new_relic`: a relic or rune gained at least three floors after the last plan
- `jev_uncertain`: after Jev answers, confidence below `CLAUDE_ESCALATE_BELOW` (default 0.35) on a card reward, shop, Hextech rune or rest site, once per screen. Jev is asked again with the new plan.

Forced transitions never trigger a request. Replaying the recorded 640-move A0 run through these triggers gives 30 requests (9-12 per act). That count uses the old run's confidences, so it estimates frequency only; it says nothing about playing strength.

**Plan.** A fixed JSON schema: archetype, summary, up to five priorities, combat risk/potion/focus, card-reward wants/avoids/skip rule, shop gold reserve and priorities, route, rest policy, replan HP threshold, and optional `allowed_option_ids` for the current non-combat screen. Jev receives the stable fields as `run_strategy` plus an instruction that live rules and legal actions take precedence.

**Constrained vs advisory** (`CLAUDE_PLAN_MODE`, default `constrained`). Constrained mode removes options outside Claude's `allowed_option_ids` on that exact screen (matched by command and label, so a reroll or purchase can't redirect an index), and removes purchases that would take gold below `shop.gold_reserve`. If only one option remains, it executes without a Jev call (`decisionSource: claude`). Advisory mode passes the same choices to Jev as `recommended_options` and removes nothing. Every execution still goes through the runner's freshness check, pause and dispatch logging.

**Session channel.** The runner writes `.private/sts2/strategy/request.json` and waits for `answer.json` with the same request ID for as long as it takes (since 2026-09-28 there is no timeout, so Claude strategy mode never hands a strategist decision to Jev). Pause cancels a wait. `CLAUDE_STRATEGIST=off` restores Jev-only play. The dashboard uses neutral wording ("strategist"). Its strategy box, below the run stats, shows the request and answer counts, the plan archetype and a labelled current status, then two toggles that start closed: Plan details (priorities, fight plan, combat, card rewards, shop, route, rest, last choice) and History that lists the last 50 answers, newest first. Each entry in the decision stream is labelled Strategist, Jev, Replay or Forced, with any strategist constraint that limited Jev.

**Operating as strategist (Claude Code session):**

1. Start a background watcher: `npm run sts2:strategy -- wait`. It exits when an unanswered request exists, which wakes the session.
2. `npm run sts2:strategy -- show` prints the instructions, schema and brief (compact deck, relics, runes, HP, gold, history summary, enemies or current options, previous plan).
3. Write the plan JSON to a scratch file and deliver it with `npm run sts2:strategy -- answer <id> <file>`. The CLI rejects schema errors, invalid option IDs, and a request that has since been replaced.
4. Restart the watcher.

Claude usage counts against the subscription, not TypeSafe tokens. Requests and plans are logged in the run's `.jsonl` as `strategy_request`, `strategy_adopted` and `replay_diverged` events.

Status: unit and integration tests cover triggers, constraints, validation, the file channel, escalation, waiting without timeout and cancellation. Live cycle verified on 2026-09-28 in two seeded standard A0 runs (JEV1: lost at the Act 2 boss, floor 33; JEV2: lost at the Act 3 boss, floor 48), with Claude answering run-start, route, shop, elite, boss, card-reward and low-HP requests through the file channel. Those runs used advisory combat plans.

## Scorecard

`npm run sts2:scorecard` (add `--json`, `--since <ISO time>`, or `--all` to include runs under 5 moves) summarizes every logged run: modifier (standard or Hextech Mayhem), policy, result, floor, and for each boss the percentage of HP removed (a later floor counts as a kill), entry HP, potions held and rounds. It also reports elites fought versus elites chosen when optional, relics and gold at the end, potions used in hallway fights, moves and Jev input tokens. Floor reached alone can't separate runs that all die at the Act 1 boss.
